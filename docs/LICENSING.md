# Лицензии Протокола: руководство владельца продукта

Документ для того, кто выдаёт лицензии. Приложение проверяет только подпись, поэтому
выдать лицензию может только тот, у кого есть закрытый ключ подписи. Ключ нигде, кроме
своего хранилища, не лежит и в репозиторий не попадает.

## 1. Ключ подписи

Ключ создаётся один раз:

```bash
python3 tools/license_tool.py keygen
```

Файл появляется в `~/.config/protokol/license-signing.key` с правами 0600. Команда
печатает открытый ключ. Сверьте его с `PUBLIC_KEY_HEX` в `api/licensing.py`: в
приложение вшит именно он.

- Сделайте резервную копию файла ключа сразу, в двух местах: зашифрованный образ или
  менеджер паролей. Потеря ключа означает, что новые лицензии нельзя выдать так, чтобы
  их приняли уже установленные приложения.
- Команда `keygen` не перезаписывает существующий ключ без `--force`. Используйте `--force`
  только сознательно: старые лицензии перестанут проверяться.
- Репозиторий хранит только открытый ключ. Закрытый ключ в git, в почту, в облачные
  заметки и на общие диски не попадает.

## 2. Выдача лицензии

```bash
python3 tools/license_tool.py issue \
    --customer "ООО Ромашка" --edition team --seats 25 \
    --expires 2027-10-14 --out romashka.license.json
```

- `--edition`: `personal`, `team` или `enterprise`. Издание только пишется в файл: приложение
  по нему ничего не отключает. Различия между изданиями — в коммерческих условиях.
- `--seats`: число мест, записывается в файл для сведения.
- `--expires`: дата окончания `ГГГГ-ММ-ДД`. Без `--expires` лицензия бессрочная.
- Файл `romashka.license.json` передаётся заказчику как есть. Он подписан, но не
  секретен: в нём название заказчика, издание, места и срок.

Заказчик устанавливает файл в приложении: настройки, раздел «Лицензия».

## 3. Продление и отзыв

- Продление: выдайте новый файл с новым сроком. Установка поверх старого заменяет его.
- Отзыва по сети нет: приложение не обращается к поставщику. Выданную лицензию можно
  только дождаться до срока окончания.
- Срочный отзыв возможен только выпуском новой сборки с новым открытым ключом. Старые
  лицензии после этого перестанут проверяться, и это касается всех заказчиков.

## 4. Смена ключа

Смена ключа — это новая сборка приложения с новым `PUBLIC_KEY_HEX` и новые лицензии
всем заказчикам. Делайте её только в крайнем случае, например если закрытый ключ
скомпрометирован.

## 5. Что проверить перед выдачей

- Открытый ключ в собранном приложении совпадает с `keygen`.
- Выданный файл принимается установленным приложением, а изменённый (например, с другим
  числом мест) отклоняется. Проверить можно на тестовой машине.
- Срок указан так, как вы обещали заказчику.
