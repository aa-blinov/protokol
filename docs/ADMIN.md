# Протокол: руководство администратора

Версия 0.1.0. Документ для тех, кто ставит приложение на Mac в организации: что
находится на машине, как задать правила организации, как работает лицензия, где
хранятся данные и как их удалить. Продуктовое описание — в [PRODUCT.md](PRODUCT.md),
технические детали сборки — в [DESKTOP.md](../DESKTOP.md), выдача лицензий —
в [LICENSING.md](LICENSING.md).

## 1. Что нужно

- Mac с Apple Silicon (M1–M4), macOS 13 или новее.
- FileVault включён. Приложение проверяет это и предупреждает в настройках, если
  FileVault выключен: тогда файлы истории лежат на диске без шифрования.
- Сеть нужна для двух вещей: выжимки (один адрес сервиса) и первой загрузки моделей
  с Hugging Face, около 620 МБ, один раз. После этого расшифровка и маскирование
  работают без сети. Загрузку моделей можно запретить политикой (`allow_model_download`),
  тогда файлы кладут в папку вручную.

## 2. Что где лежит на машине

| Путь | Что там | Права |
| --- | --- | --- |
| `/Applications/Протокол.app` | приложение без моделей | как у установщика |
| `~/Library/Application Support/sttshka-desktop/sessions.json` | история: расшифровка с именами, таблица соответствий, выжимки | 0600 |
| `…/sttshka-desktop/.env` | адрес сервиса, модель, ключ провайдера, срок хранения | 0600 |
| `…/sttshka-desktop/cache/*.json` | кэш распознавания, последние 8 записей, с расшифровкой | 0600 |
| `…/sttshka-desktop/trial.json` | дата первого запуска (отсчёт пробного периода) | 0600 |
| `…/sttshka-desktop/license.json` | установленная лицензия (подписанный файл) | 0600 |
| `…/sttshka-desktop/models/` | модели распознавания, поиска персональных данных и диаризации, скачанные при первом запуске | обычные; это общедоступные файлы моделей, не данные |
| `/Library/Application Support/Protokol/policy.json` | политика организации, если задана | пишет администратор |

Аудиофайл приложение не сохраняет: он читается в память и декодируется во временную
папку, которая удаляется после распознавания.

## 3. Политика организации

Администратор задаёт правила одним файлом. Приложение читает его при старте, поэтому
после изменения нужен перезапуск. Готовый пример — [policy.example.json](policy.example.json);
значения ключей описаны в таблице ниже.

| Ключ | Что делает | По умолчанию |
| --- | --- | --- |
| `base_url` | фиксирует адрес сервиса; в приложении его нельзя поменять | не фиксирован |
| `lock_settings` | запрещает менять любые настройки в приложении (поля отключены) | `false` |
| `retention_days` | удаляет записи старше N дней вместе с расшифровкой и кэшем, 1–3650 | не задано |
| `allow_export` | `false` прячет «Скачать .txt», «Печать / PDF» и кнопки «Скопировать» | `true` |
| `allow_model_download` | `false` запрещает загрузку моделей из интернета; файлы кладутся в папку моделей вручную | `true` |
| `zdr` | `true` разрешает только провайдеров с политикой нулевого хранения | `false` |
| `data_collection` | `"deny"` просит провайдера не сохранять и не обучаться на запросах; `"allow"` — нет | `"deny"` |

Ошибки в файле не останавливают приложение. Неверное значение пропускается и
показывается в настройках и в `GET /api/health` (поле `policy.errors`), а остальные
правила применяются. Неизвестный ключ тоже попадает в список ошибок: опечатка не
отключает правило молча.

Что видит пользователь: в настройках вверху написано «Настройки задаёт организация»,
зафиксированные поля отключены, а не скрыты, чтобы было видно, что задано.

Политика не отменяет маскирование. Она задаёт, куда уйдёт текст и как долго он
хранится; маскирование действует всегда.

## 4. Лицензия

Приложение работает бесплатным пробным периодом 14 дней с первого запуска. Дальше
нужна лицензия — подписанный файл, который выдаёт поставщик (см. [LICENSING.md](LICENSING.md)).

- Установка: в настройках раздел «Лицензия», выбрать полученный файл. Файл проверяется
  по подписи поставщика, и при любом изменении содержимого установка отклоняется.
- Срок: лицензия может быть бессрочной или действовать до даты. После истечения
  приложение перестаёт распознавать и составлять выжимки; история остаётся доступной,
  ничего не удаляется.
- Проверка работает без сети: лицензия не связана с машиной и не проверяется у
  поставщика. Число мест указано в файле, но в офлайн-режиме приложение его не считает.
- Продление: поставщик выдаёт новый файл с новым сроком. Установите его поверх старого.

## 5. Хранение и удаление данных

- Срок хранения задаётся политикой (`retention_days`) или пользователем в настройках.
  По умолчанию записи не удаляются. Это сделано намеренно: автоматическое удаление
  без согласия владельца данных может стереть то, что нужно.
- Удаление записи в приложении убирает её из истории и удаляет её кэш распознавания с диска.
  Срок хранения работает так же: записи старше срока удаляются из файла истории и из кэша.
- Резервные копии (например, Time Machine) содержат эти файлы. Если это недопустимо,
  исключите папку `sttshka-desktop` из резервного копирования.
- Полное удаление с машины: закрыть приложение, удалить `/Applications/Протокол.app`,
  папку `~/Library/Application Support/sttshka-desktop/`, файл политики (если был), и
  очистить Корзину.

## 6. Сеть и провайдер

Наружу уходит только то, что нужно для выжимки: маскированный текст с метками
спикеров и таймкодами, инструкция выбранного режима и требования пользователя (если в
них были персональные данные, в запрос уходят метки). Ключ провайдера хранится на Mac и
передаётся провайдеру при запросах.

Модели приложение берёт из публичных репозиториев Hugging Face: GigaAM v3 (MIT), ruBERT
PII NER (Apache-2.0), сегментация pyannote (MIT) и CAM++ (Apache-2.0). Каждый файл
закреплён за ревизией репозитория и проверяется по SHA-256 до того, как попадает в папку
приложения. Запрос обычный: без учётной записи, без токена и без идентификаторов
человека или устройства. Если сеть закрыта, задайте `allow_model_download: false` и
положите файлы в `~/Library/Application Support/sttshka-desktop/models/` тем же путём
вручную: список файлов и их хэши есть в `api/model_store.py`.

Сервис задаётся адресом. Подойдёт любой сервис с OpenAI-совместимым API, включая
внутренний шлюз организации. Если нужна работа только с внутренним шлюзом, задайте его
адрес в `base_url` и включите `lock_settings`.

## 7. Обновления

Автообновления в версии 0.1.0 нет. Новая версия ставится вручную: новой сборкой
поверх старой. Перед установкой поверх старого приложения удалите старое целиком:
`ditto` в существующий каталог дописывает файлы, и подпись перестаёт проходить проверку
(см. DESKTOP.md, раздел «Обновление поверх старой копии»).

## 8. Чего в версии 0.1.0 нет

- Журнала действий. История хранит записи, но не фиксирует каждую отправку модели.
- Шифрования файлов поверх FileVault. Защита — права доступа 0600 и FileVault.
- Автообновления и централизованного управления через MDM-профиль: политика — это
  файл, его раскладывает администратор.
- Проверки лицензии по сети и учёта мест на машинах.

## 9. Диагностика

`GET /api/health` отдаёт состояние. Порт сервиса меняется при каждом запуске, поэтому оболочка
приложения выводит актуальный адрес в свой stdout (см. DESKTOP.md):

- `license` — состояние лицензии: `trial`, `licensed` или `expired`, сколько дней осталось;
- `policy` — подключена ли политика и список её ошибок;
- `filevault` — включён ли FileVault (`null`, если проверить нельзя);
- `retention_days` — действующий срок хранения;
- `llm_configured` — задан ли ключ провайдера.

Если приложение не запускается, оно показывает хвост лога сайдкара: обычно причина в
отсутствии моделей или в неверном Python (см. DESKTOP.md).
