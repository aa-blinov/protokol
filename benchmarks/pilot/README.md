# Пилотная оценка маскирования

`benchmarks/pilot_eval.py` измеряет, как приложение маскирует персональные данные в записях клиента.
Записи и их разметка — данные клиента. Папка `benchmarks/pilot/data/` добавлена в `.gitignore`:
gold-файлы кладите туда и никуда не коммитьте.

## Gold-файл

Один JSON на запись:

```json
{
  "recording": "call-07",
  "asr_text": "Спикер 1 [0:00]: Меня зовут Анна, телефон 8 900 123-45-67.",
  "spans": [
    {"start": 28, "end": 32, "type": "PERSON"},
    {"start": 42, "end": 57, "type": "PHONE"}
  ],
  "asr_missed": [
    {"type": "PHONE", "time": "1:05", "note": "назван второй номер, распознавание его не записало"}
  ]
}
```

- `recording` — id записи, нейтральный код (`call-07`), не имя человека.
- `asr_text` — текст ровно таким, каким его выдало распознавание, с репликами `Спикер N [m:ss]: ...`.
- `spans` — персональные данные в `asr_text`: фрагмент это `asr_text[start:end]`, `end` не входит.
  Смещения в символах Python (кодовых точках), а не в UTF-16 из JavaScript.
  Нужно `0 <= start < end <= длина`, во фрагменте хотя бы одна буква или цифра, фрагменты не пересекаются.
- `type` — один из: PERSON, ADDRESS, PHONE, EMAIL, URL, IP, PASSPORT, INN, SNILS, OMS, DRIVER_LICENSE,
  MILITARY_ID, BIRTH_CERTIFICATE, CARD, SECRET, OGRNIP, ORG_ID, NUMBER.
- `asr_missed` — необязательно, по умолчанию пусто. Персональные данные, которые слышны в записи,
  но распознавание написало неверно или не написало совсем. Считаются отдельно и в покрытие не входят.
  `time` — где искать в записи. `note` — пояснение, в отчёт и вывод не попадает.

Других полей верхнего уровня быть не должно: лишнее поле (например, опечатка в `asr_missed`) отклоняет файл.
Отклонённый файл называется в выводе с причиной, остальные считаются.

## Запуск

```
api/.venv/bin/python benchmarks/pilot_eval.py benchmarks/pilot/data \
  --report ~/pilot-reports/report.md --json ~/pilot-reports/report.json
```

Коды выхода: 0 — все файлы приняты, 1 — часть отклонена, 2 — не принят ни один файл
(или нет папки, или модель маскирования не загрузилась).

`--examples` печатает пропущенные фрагменты с текстом. Текст выводится только в терминал, в файлы
не пишется: не перенаправляйте этот вывод в файл.

## Что считается

Маска та же, что у приложения: `main._spans` и `masking.hidden_spans`, как в `run_pii_bench_ru.py`.

- Покрытие букв — доля букв, цифр и подчёркиваний эталонных фрагментов, попавших в маску.
  Тип метки приложения не сверяется: фрагмент считается скрытым, чем бы он ни был помечен.
- Полностью — фрагменты, у которых все такие символы замаскированы. Пропущено — все остальные.
- ASR не дал — записи `asr_missed`, отдельным столбцом.
- Лишние маски — символы, замаскированные вне всех эталонных фрагментов. Пробелы и знаки внутри
  склеенной маски тоже считаются.

## Приватность

- `--report` и `--json` содержат только счётчики и id записей: без текста, примеров и смещений.
- Сообщения об ошибках называют файл и номер элемента, значений из файла не показывают.
- Отчёты держите вне репозитория.
